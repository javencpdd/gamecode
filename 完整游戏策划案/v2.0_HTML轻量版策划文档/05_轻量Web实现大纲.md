# 《力学大乱斗》轻量 Web/HTML 实现大纲

版本：v2.0  
文档定位：HTML 小游戏导出目标、体积预算、技术架构、素材策略与开发范围

---

## 1. 实现目标

v2.0 的目标不是做一个大型 Web 游戏，而是做一个可以快速打开、容易分享、文件体积小、无需安装的 HTML 小游戏。

优先目标：

1. 可以直接在浏览器打开。
2. 首版尽量导出为单个 `index.html`。
3. 没有大型第三方引擎依赖。
4. 图形、特效、UI 尽量由代码绘制。
5. 核心玩法完整：卡牌驱动位移、掷骰、碰撞、出界、胜负。

---

## 2. 文件体积预算

| 版本 | 目标体积 | 内容范围 |
| --- | --- | --- |
| MVP | 尽量小于 1 MB | 2 角色、12 张卡、1-2 地图、本地 1v1 |
| Demo | 尽量小于 3 MB | 3 角色、24-36 张卡、3-4 地图、基础音效 |
| 轻量完整版 | 尽量小于 5 MB | 6-8 角色、60-90 张卡、8 张地图 |

说明：

- 体积目标以未压缩静态文件为参考，实际发布可用 gzip/brotli 进一步压缩。
- 若平台要求单文件 HTML，图片和音效应尽量避免 base64 内嵌大资源。
- 首版宁可少内容，也要保证打开快、运行稳定、规则清楚。

---

## 3. 推荐技术架构

### 3.1 首版架构

推荐：

- HTML：页面结构、Canvas 容器。
- CSS：基础布局、按钮、手牌样式。
- JavaScript：游戏循环、物理、卡牌、状态、UI。
- Canvas 2D：战斗场景、角色、粒子、轨迹线。
- WebAudio：合成短音效。

不推荐首版使用：

- Phaser.js。
- Matter.js。
- Three.js。
- 大图集。
- 大量 PNG/JPG 背景。
- mp3/ogg 长音频。
- 复杂构建工具链。

### 3.2 文件组织

单文件方案：

```text
index.html
```

适合黑客松、网页托管、直接分享。

少文件方案：

```text
index.html
style.css
game.js
```

适合后续维护，仍然很轻。

### 3.3 代码模块建议

即使写在一个 JS 文件里，也建议按模块组织。

| 模块 | 职责 |
| --- | --- |
| `Game` | 主循环、状态切换、胜负 |
| `Renderer` | Canvas 绘制 |
| `Physics` | 简化碰撞、冲量、摩擦、出界 |
| `Cards` | 卡牌数据和效果函数 |
| `Dice` | D6 掷骰和修正 |
| `Input` | 选卡、瞄准、确认、取消 |
| `UI` | 手牌、能量、血量、提示 |
| `Audio` | WebAudio 合成音效 |

## 4. 简化物理方案

### 4.1 碰撞体

首版只使用圆形碰撞体。

| 实体 | 碰撞体 |
| --- | --- |
| 玩家 | 圆形 |
| 训练假人 | 圆形 |
| 普通障碍 | 圆形或轴对齐矩形 |
| 场地边界 | 圆形半径或矩形边界 |
| 区域效果 | 圆形范围 |

### 4.2 物理参数

每个实体保留最小字段：

```js
{
  x, y,
  vx, vy,
  radius,
  mass,
  friction,
  charge,
  stability,
  statuses
}
```

### 4.3 每帧更新

```text
处理输入
更新卡牌倒计时
应用持续场效果
积分速度和位置
应用摩擦
处理碰撞
处理出界
更新 UI
绘制画面
```

### 4.4 简化碰撞

只做圆形碰撞：

```text
如果两个圆距离小于半径和：
  推开重叠
  根据相对速度计算冲量
  根据速度计算结构伤害
```

这种方案体积小、易调试、手感足够支撑首版。

## 5. 渲染策略

### 5.1 战斗画面

用 Canvas 绘制：

- 场地边界。
- 地面网格。
- 玩家圆形核心。
- 角色状态环。
- 速度拖尾。
- 卡牌影响范围。
- 粒子特效。
- 骰子动画。

### 5.2 角色表现

不使用大尺寸角色图片。

建议：

- 艾萨克：蓝色方形/圆角重核，厚拖尾。
- 麦克斯韦：黄色圆形核心，红蓝电荷环。
- 芝诺：绿色多边形核心，分段残影。

### 5.3 卡牌 UI

卡牌可用 HTML/CSS 绘制：

- 卡牌名称。
- 消耗数字。
- 属性颜色。
- 简单符号。
- 冷却或不可用遮罩。

不建议首版给每张卡做独立大图。

---

## 6. 音效策略

首版优先使用 WebAudio 合成短音。

可合成音效：

- 冲刺：短上滑频率。
- 撞击：低频噪声 + 快速衰减。
- 电磁：高频脉冲。
- 掷骰：短点击声。
- 出界：下滑音。

优势：

- 不增加音频文件体积。
- 可用代码动态改变音高和音量。
- 适合轻量 HTML。

## 8. 体积控制清单

### 8.1 应该做

- 用 Canvas 画角色和特效。
- 用 CSS 做卡牌 UI。
- 用 JS 对象存卡牌数据。
- 多张卡复用效果函数。
- 粒子复用对象池。
- 地图使用参数生成。
- 音效用 WebAudio 合成。
- 首版只做本地 1v1。

### 8.2 暂时不要做

- 大尺寸立绘。
- 多帧序列动画。
- 每张卡独立插画。
- 长背景音乐。
- 第三方物理引擎。
- 复杂联机。
- 皮肤系统。
- 过多地图和角色。

## 11. 验收标准

v2.0 MVP 完成时应满足：

1. 双击或打开 `index.html` 能进入游戏。
2. 不需要安装依赖。
3. 不需要联网。
4. 文件体积尽量小于 1 MB。
5. 两名玩家能通过卡牌改变位置并完成击飞。
6. 掷骰、能量、手牌和出界规则都能看懂。
7. 一局能在 3-6 分钟内结束。

---

## 12. 后续扩展边界

如果要继续扩展，应优先扩展“数据”，谨慎扩展“引擎”。

优先级：

1. 增加卡牌数据。
2. 增加地图参数。
3. 增加角色参数。
4. 增加少量新效果函数。
5. 最后再考虑第三方库或联机。

只要核心体验成立，轻量 HTML 版本的优势就是打开快、分享快、修改快。
