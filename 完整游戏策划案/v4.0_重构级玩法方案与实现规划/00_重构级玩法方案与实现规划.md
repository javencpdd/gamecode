# 《力学大乱斗》v4.0 重构级玩法方案与实现规划

版本：v4.0  
日期：2026-05-16  
适用工程：Cocos Creator 3.8.8 2D 双人对战原型  
文档定位：用于评审 v3.0 即时结算 MVP 向 v4.0 “回合内规划 + 回合末统一物理结算”版本的系统重构方案

---

## 1. 系统级可行性分析

v4.0 的核心方向是可行的，但它不再是对 v3.0 单脚本 MVP 的小改，而是一次玩法架构重构。原因是结算模型从“卡牌立即产生速度/冲量”变成“卡牌创建或修改物理系统中的持续因素，再由统一物理结算计算移动”。

可行点：

- Cocos Creator 3.8.8 能承载 2D 绘制、输入、UI、倒计时、骰子动画和轻量物理模拟。
- 当前 MVP 已有角色、手牌、回合、场景绘制、拖拽输入、出界判定等基础，可作为原型验证资产。
- 1 秒逻辑步长适合策略规划：玩家能理解“这个效果会在下一秒发生什么”。
- 固定场源、墙体、属性修改、数学卡牌都可以用数据驱动方式实现，适合后续扩展卡池。

主要挑战：

- “固定 1 秒逻辑步长”与“视觉平滑移动”有天然冲突。建议规则层以 1 秒为权威步长，表现层用插值或 0.1 秒子步展示过程，不改变结算结果。
- “取消基础力”会显著降低卡牌直接反馈，需要用场源、属性改变、墙体布局和持续效果补足可操作性。
- 同时作用的持续效果可能快速堆叠，必须有上限、同类叠加规则和生命周期管理。
- 增加数学卡牌后，数值爆炸风险很高，必须限制作用对象、范围、最小值、最大值和每回合可修改次数。
- 三局两胜加每局最多 30 个行动回合会拉长单局时长。2 分钟行动时限是上限，不应成为常态节奏。建议加入 15 秒、30 秒的催促提示，并支持玩家主动结束。

结论：

v4.0 值得推进，但 P0 阶段必须先做“统一结算内核 + 单位体系 + 数据化效果队列”，不要同时追求完整 UI、音效、像素美术和大卡池。玩法上应优先验证：玩家是否能通过规划场源和属性变化，预测 1 秒后的运动结果。

## 2. 相比即时结算 MVP 需要重构的核心模块

| 现有 MVP 模块 | v3.0 状态 | v4.0 重构方向 |
| --- | --- | --- |
| 回合控制 | 出牌后立即结算，结算完可继续或换人 | 行动回合内规划，多张卡进入待结算队列，结束回合后统一结算 |
| 卡牌效果 | 卡牌直接产生基础力、冲量、速度改变 | 卡牌创建场源、修改属性、创建/破坏墙体、添加数学变换 |
| 物理结算 | 每帧简化速度、摩擦、碰撞 | 固定 1 秒规则步长，按合力、质量、摩擦、环境约束计算 |
| 状态持续 | 按回合扣减，逻辑散落在单脚本 | EffectInstance 数据化，包含 owner、target、duration、remaining、tick rule |
| 数值体系 | 像素、速度、力混用 | 建立 SI 风格单位：kg、m、m/s、C、N、kg·m/s，并定义像素换算 |
| 输入系统 | 拖卡释放即生效 | 拖卡放置意图：设置目标、位置、方向、参数，进入计划槽 |
| UI | 原型 HUD | 开始界面、行动倒计时、计划区、待结算列表、骰子过场、结算回放 |
| 场景 | 只有实验台边界 | 增加刚性墙体、固定场源、环境对象生命周期 |
| 胜负 | 先到 3 分 | 三局两胜；单局出界胜；30 行动回合后按中心距离判胜 |

## 3. 目标玩法主循环

推荐把“整场比赛、单局、行动回合、物理秒”分清楚。

1. 进入像素风开始界面。
2. 玩家点击开始，播放先手骰子动画。
3. 骰子点数 1 到 3：牛顿先手；点数 4 到 6：麦克斯韦先手。
4. 进入第 1 局，双方重置位置、属性、手牌、场景。
5. 当前玩家进入行动回合，倒计时 120 秒。
6. 当前玩家可以出多张卡、弃牌、查看卡牌说明、设置场源位置或方向。
7. 卡牌不立即生效，不改变正式角色属性，不创建正式场景对象，只进入“本回合计划队列”。
8. 玩家点击结束，或 120 秒超时，行动回合结束。
9. 播放回合末骰子过场动画。
10. 动画结束后，本回合计划队列才转化为正式效果。
11. 结算时，本回合新效果、之前仍在持续时间内的效果、地图墙体和固定场源同时参与。
12. 以 1 秒规则步长计算合力、加速度、速度、位移、摩擦、碰撞、墙体阻挡、出界；双方角色都可能移动。
13. 若有人出界，单局结束。
14. 若无人出界，所有持续效果扣减 1 秒生命周期，过期效果移除。
15. 切换到下一名玩家行动回合。
16. 单局最多 30 个行动回合，双方各 15 回合。若未出界，比较双方到中心点距离，距离更远者失败。
17. 先赢 2 局者获得整场胜利。

术语说明：2 分钟是单个行动回合的规划上限；30 是单局行动回合数量上限，不是 30 秒总局时长。

## 4. 建议系统模块拆分

### 4.1 MatchController

职责：

- 管理三局两胜。
- 管理开始界面到战斗场景的状态切换。
- 管理先手骰子结果。
- 记录单局胜负和整场胜负。

### 4.2 RoundController

职责：

- 管理单局开始、单局结束、30 行动回合上限。
- 管理当前行动玩家。
- 管理出界判定和距离中心判定。

### 4.3 TurnController

职责：

- 管理 120 秒行动倒计时。
- 管理当前玩家计划队列。
- 管理结束、超时、弃牌和手牌补充。
- 触发骰子过场与统一结算。

### 4.4 CardSystem

职责：

- 读取卡牌定义。
- 判断卡牌合法性。
- 生成计划项 CardIntent。
- 生成持续效果 EffectInstance。
- 处理弃牌、抽牌、手牌上限。

### 4.5 PhysicsWorld

职责：

- 使用统一单位体系保存角色、墙体、场源。
- 每次结算执行 1 秒规则步长。
- 汇总所有受力，计算速度、位置、摩擦和碰撞。
- 提供调试数据给 HUD 显示。

### 4.6 EffectSystem

职责：

- 管理持续效果生命周期。
- 支持固定场源、属性修正、墙体生成、墙体破坏、数学变换。
- 在每个结算 tick 前向 PhysicsWorld 提供有效效果。

### 4.7 EnvironmentSystem

职责：

- 管理刚性墙体。
- 管理可破坏墙体生命值。
- 管理固定电荷点、风场等地图场源。
- 管理环境对象的创建、持续、移除。

### 4.8 BattleHud

职责：

- 显示行动倒计时、手牌、弃牌、计划队列、当前单位数值。
- 显示角色质量、摩擦系数、速度、电荷、合力、动量。
- 显示结算回放中的关键数值。

### 4.9 DicePresentation

职责：

- 负责先手骰子动画。
- 负责回合末骰子过场。
- 将骰子结果传给 TurnController 或 CardSystem。

## 5. 卡牌系统重构建议

### 5.1 取消基础力后的设计原则

v4.0 不再允许卡牌直接写入“基础力”或直接给角色冲量。卡牌只能通过以下方式影响物理：

- 创建固定场源：固定电荷点、风场、引力点、摩擦区。
- 修改角色自身属性：质量、电荷、摩擦系数、形状半径、速度阻尼。
- 修改环境：添加墙体、破坏墙体、改变墙体属性。
- 修改规则变量：效果持续时间、场源强度倍率、作用范围。
- 应用数学卡牌：对合法属性做加、减、乘、除变换。

建议所有卡牌输出统一为 CardIntent：

```text
CardIntent = {
  owner,
  cardId,
  targetType,
  targetId,
  placement,
  direction,
  parameters,
  createdTurn,
  previewData
}
```

回合结束后 CardIntent 再转化为 EffectInstance 或一次性规则操作。

重要时序约束：

- CardIntent 在行动回合内只是计划数据。
- CardIntent 不会立刻改变 CharacterState、FieldSource 或 WallBody。
- 玩家可以看到预测值，但预测值不等于正式状态。
- 只有回合结束且骰子过场完成后，CardIntent 才能转换为正式效果并参与 1 秒结算。

### 5.2 数值设计方式

推荐从“基础力”转为“三层数值”：

1. 物理属性层：质量 kg、电荷 C、摩擦系数、位置 m、速度 m/s。
2. 场源参数层：场源强度、范围、方向、持续秒数、衰减曲线。
3. 规则约束层：最大叠加数、最小值、最大值、同类覆盖规则。

示例：

| 卡牌类型 | 不再做什么 | 改为做什么 |
| --- | --- | --- |
| 推击牌 | 不直接给 200 基础力 | 放置 1 秒风场，方向由鼠标设置，强度 0.8 N |
| 吸引牌 | 不直接拉对手 | 放置固定电荷点，产生小范围库仑吸引 |
| 回场牌 | 不直接把自己推回中心 | 临时降低自身摩擦，或增加中心弱引力场 |
| 防守牌 | 不直接抵消冲量 | 增加自身质量或摩擦系数，持续 1 到 2 秒 |

### 5.3 掷骰在 v4.0 的定位

需要提前拍板。推荐方案：

- 先手骰子：必须决定先手。
- 回合末骰子：作为过场和实验波动，仅影响明确写有“骰子点数”条款的卡牌。
- 默认卡牌不吃全局骰子倍率，避免玩家规划失真。

不推荐继续让所有卡牌统一乘骰子倍率。原因是 v4.0 强调规划和真实物理，隐藏倍率会削弱玩家计算感。

### 5.4 卡组落地范围

v4.0 必须把卡牌从“效果按钮”升级为可配置卡组。P0 至少包含：

- 基础共通卡组：弱风场、弱电荷点、摩擦区、临时墙、破墙、质量/摩擦/电荷校准。
- 基础数学卡组：加一、减一、倍率放大、半值衰减，严格执行白名单和边界。
- 牛顿专属卡组：质量、惯性、摩擦、墙体吸收和破墙。
- 麦克斯韦专属卡组：固定电荷点、双极子、风场、电荷翻转和场源强化。

完整卡牌清单、角色初始属性、抽牌和弃牌规则见 `02_卡组与卡牌设计.md`。

## 6. 数学卡牌、固定场源、墙体系统规则建议

### 6.1 数学卡牌

数学卡牌只允许作用于明确白名单属性：

- 质量 massKg
- 电荷 chargeC
- 摩擦系数 friction
- 场源强度 fieldStrength
- 场源持续时间 durationSec
- 墙体耐久 wallHp

禁止直接修改：

- 位置 position
- 出界状态
- 胜负分数
- 行动回合数
- 当前速度方向
- 瞬时动量

推荐边界：

| 属性 | 最小值 | 最大值 | 说明 |
| --- | --- | --- | --- |
| 质量 | 0.5 kg | 5.0 kg | 过小会导致加速度爆炸 |
| 电荷 | -5 C | 5 C | 绝对值越大越危险 |
| 摩擦系数 | 0.02 | 0.80 | 不允许为 0 或负数 |
| 场源强度 | 0.05 N | 2.00 N | 固定场源必须偏小 |
| 持续时间 | 1 s | 5 s | MVP 阶段不建议更长 |
| 墙体耐久 | 1 | 5 | 低数值便于理解 |

数学操作建议：

- 加法：`x = clamp(x + a, min, max)`
- 减法：`x = clamp(x - a, min, max)`
- 乘法：`x = clamp(x * r, min, max)`，倍率建议 0.5 到 2.0。
- 除法：`x = clamp(x / r, min, max)`，除数必须大于等于 2，禁止除以 0 和接近 0 的数。

每名玩家每个行动回合最多使用 1 张数学卡牌。这个限制能避免属性被一回合连锁改爆。

### 6.2 固定场源

固定场源是 v4.0 的核心。

推荐类型：

| 场源 | 玩家设置 | 作用方式 | MVP 强度建议 |
| --- | --- | --- | --- |
| 固定电荷点 | 鼠标设置位置 | 按电荷正负吸引或排斥角色 | 最大 1.2 N |
| 固定方向风场 | 鼠标设置位置和方向 | 范围内角色受到固定方向小力 | 最大 0.8 N |
| 中心弱引力 | 选择目标区域 | 角色朝区域中心受力 | 最大 0.6 N |
| 摩擦区 | 鼠标设置位置 | 改变范围内摩擦系数 | 0.05 到 0.30 |

边界约束：

- 场源必须有半径范围，默认 2 m 到 4 m。
- 场源强度偏小，不能单独完成击杀。
- 同类场源最多同时存在 3 个。
- 同一玩家最多控制 3 个场源。
- 场源必须显示影响范围、方向箭头和剩余秒数。

### 6.3 墙体系统

墙体定位是环境约束，不是弹球板。

规则建议：

- 墙体为固定形状刚体，默认矩形或线段墙。
- 墙体不可弹性反弹，碰撞恢复系数 restitution = 0。
- 角色撞墙后，法线方向速度被吸收，切线方向按摩擦保留或衰减。
- 墙体可被卡牌添加，持续 1 到 5 秒。
- 墙体可被破坏，耐久 1 到 5。
- 墙体不能生成在角色重叠位置。
- 墙体不能完全封死角色，至少保留可移动通道。
- 每名玩家最多同时拥有 2 段临时墙。

替代建议：

如果 v4.0 P0 难以实现任意墙体放置，先做固定点位墙体：玩家只能在地图预设插槽上添加或破坏墙体。这样能显著降低碰撞和合法性判断难度。

## 7. 表现系统优先级建议

| 表现项 | 优先级 | 理由 |
| --- | --- | --- |
| 结算数值调试 HUD | P0 | 没有数值显示无法验证物理规则 |
| 回合末骰子过场 | P1 | 规则要求存在，但可先用简单动画 |
| 像素风开始界面 | P1 | 提升完整感，并承载先手骰子 |
| 场源范围与方向可视化 | P0 | 玩家必须知道自己放置了什么 |
| 墙体放置预览 | P0 | 防止非法放置和误操作 |
| 角色受力箭头 | P1 | 帮助理解合力和运动 |
| 特效音效 | P2 | 能增强反馈，但不应早于规则稳定 |
| 完整像素美术重绘 | P3 | 在玩法未定前不建议投入大规模美术 |

骰子动画建议：

- P0：纯 UI 数字滚动，持续 0.8 秒。
- P1：像素骰子帧动画，持续 1.2 秒。
- P2：加入音效、屏幕轻震、粒子。

## 8. 版本开发优先级

### P0：规则内核重构

目标：先跑通 v4.0 核心闭环。

- 拆分 Match、Round、Turn、Card、Effect、Physics 模块。
- 建立单位体系和像素换算。
- 建立 1 秒统一结算。
- 建立 CardIntent 和 EffectInstance。
- 卡牌不立即生效，进入计划队列。
- 当前回合新效果和旧持续效果共同参与结算。
- 实现角色质量、摩擦、电荷、速度、位置。
- 实现固定电荷点和固定方向风场各 1 种。
- 实现不可弹性反弹墙体的基础碰撞。
- 实现行动回合 120 秒倒计时和超时自动结束。
- 实现 30 行动回合上限和中心距离判定。

### P1：可玩性闭环

- 像素风开始界面。
- 先手骰子动画。
- 回合末骰子过场。
- 弃牌功能。
- 数学卡牌基础四则运算。
- 墙体添加和破坏卡牌。
- 结算回放与受力箭头。
- 三局两胜 UI。

### P2：体验增强

- 像素特效和音效。
- 更完整的卡牌详情面板。
- 场源叠加预览。
- 墙体合法性提示。
- 卡牌分类筛选。
- AI 或本地单人测试模式。

### P3：内容扩展

- 角色专属被动。
- 更多地图。
- 更多场源类型。
- 更多数学变换。
- 角色皮肤和动画。
- 联机前置架构验证。

## 9. 关键风险、冲突点和需要拍板的决策

### 9.1 固定 1 秒步长与碰撞稳定性

风险：1 秒步长过大，角色可能穿墙或越过碰撞体。  
建议：规则层每回合结算 1 秒，物理层内部可拆成 10 个 0.1 秒子步。对玩家仍显示为 1 秒结算，不改变规则含义。

### 9.2 回合末骰子是否影响所有卡

风险：如果骰子影响所有卡牌强度，玩家无法稳定规划。  
建议：骰子默认只用于过场和特定卡牌，不作为全局倍率。

### 9.3 取消基础力后的爽感下降

风险：玩家可能觉得卡牌“不够直接”。  
建议：用可视化强反馈补足，包括场源范围、受力箭头、角色轨迹预测和结算回放。

### 9.4 数学卡牌破坏平衡

风险：乘除法极易造成数值爆炸或锁死。  
建议：数学卡牌必须白名单属性、clamp 边界、每回合限 1 张、禁止直接改位置和分数。

### 9.5 墙体不可弹性反弹的手感

风险：墙体吸收速度后可能显得迟钝。  
建议：墙体承担“阻挡、分割、保护、压迫”功能，不承担弹射功能。需要用音效和撞击特效表现反馈。

### 9.6 2 分钟行动回合过长

风险：双人对局节奏拖慢。  
建议：2 分钟作为硬上限，默认鼓励 20 到 40 秒结束。加入倒计时催促和明确计划队列。

### 9.7 三局两胜与 30 行动回合时长

风险：整场可能过长。  
建议：P0 内部测试可先用每局 12 或 20 行动回合快速验证，正式规则保留 30 行动回合。

### 9.8 固定场源强度偏小导致不出界

风险：局面可能僵持。  
建议：30 行动回合中心距离判定兜底，同时让墙体、摩擦区和属性变化提供局部优势。

## 10. 推荐拍板项

建议立刻确定以下设计决策：

1. 规则层 1 秒结算，物理表现允许内部子步。
2. 骰子不再作为所有卡牌的统一强度倍率。
3. 卡牌不能直接施加基础力或瞬时冲量。
4. MVP 阶段数学卡牌每回合最多 1 张。
5. MVP 阶段每名玩家最多同时拥有 3 个场源、2 段临时墙。
6. 墙体碰撞不弹性反弹，法线速度吸收。
7. 单局 30 行动回合为正式上限，但调试版本可降低。
8. 中心距离判定使用角色圆心到地图中心的欧氏距离。
