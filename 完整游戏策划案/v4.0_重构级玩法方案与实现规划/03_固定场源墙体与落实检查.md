# 《力学大乱斗》v4.0 固定场源、墙体系统与落实检查

版本：v4.0  
日期：2026-05-17  
文档定位：补齐固定场源、刚性墙体的可落地规则，并检查 v4.0 目标规则在当前 MVP 中的落实状态

---

## 1. 固定场源系统设计

固定场源是放置在地图上的环境对象。场源本身不移动，角色在统一结算时根据所在位置、电荷、质量、摩擦等属性受到场源影响。

时序要求：

- 玩家在行动回合内使用场源卡时，只创建待生效场源计划，不加入正式场景。
- 玩家点击结束或 120 秒超时后，先播放回合末骰子过场。
- 骰子过场结束后，待生效场源才转化为正式 `FieldSource`。
- 正式场源会和旧的未过期场源一起参与本次 1 秒结算。
- 持续 3 s 的场源表示参与 3 次行动回合末的 1 秒结算，不是在玩家规划阶段持续逐帧生效。

### 1.1 场源通用字段

| 字段 | 说明 |
| --- | --- |
| sourceId | 场源实例 ID |
| owner | 创建者 |
| type | wind、charge、friction、damping |
| positionM | 地图坐标，单位 m |
| direction | 方向向量，仅风场需要 |
| radiusM | 作用半径 |
| strength | 强度，风场单位 N，电荷点使用游戏化强度 |
| durationSec | 剩余持续秒数 |
| maxForceN | 单个角色最多受到的力 |
| stackGroup | 叠加分组 |

### 1.2 场源叠加规则

- 同一玩家最多同时拥有 3 个场源。
- 全场同类型场源最多 5 个。
- 同一位置 0.5 m 内不能放置同类型场源。
- 同一角色受到的场源合力上限建议为 2.5 N。
- 场源持续时间每次统一结算后减少 1 秒。
- 场源强度不因骰子默认变化，只有明确写有骰子条款的卡会变化。

### 1.3 场源预览要求

玩家放置场源时，界面必须显示：

- 作用范围圆。
- 风场方向箭头。
- 电荷点正负号。
- 预计最大作用力。
- 持续秒数。
- 是否超过场源数量上限。

没有预览的场源系统不可进入 P0 验收，因为玩家无法规划。

## 2. 刚性墙体系统设计

墙体是固定形状的环境碰撞体。v4.0 的墙体不提供弹性反弹，只提供阻挡、导向、吸收速度和空间压迫。

时序要求：

- 玩家在行动回合内使用墙体卡时，只创建待生效墙体计划，不立即改变正式碰撞世界。
- 破墙卡同样只进入计划队列，不会在出牌瞬间扣除墙体耐久。
- 回合结束且骰子过场完成后，新增墙体、破墙效果和旧墙体状态一起进入本次 1 秒结算。
- 结算阶段之外，角色不会因为墙体或场源变化而移动。

### 2.1 墙体通用字段

| 字段 | 说明 |
| --- | --- |
| wallId | 墙体实例 ID |
| owner | 地图、牛顿、麦克斯韦或中立 |
| shape | rect 或 segment |
| centerM | 中心坐标 |
| sizeM | 宽高，或长度和厚度 |
| rotationDeg | 旋转角度 |
| hp | 耐久 |
| durationSec | 临时墙剩余秒数 |
| wallFriction | 墙面摩擦 |
| breakable | 是否可破坏 |
| permanent | 是否地图永久墙 |

### 2.2 P0 地图固定墙体方案

推荐 P0 地图逻辑尺寸：

```text
地图宽度：12.0 m
地图高度：6.8 m
显示换算：1 m = 100 px
中心点：(0, 0)
```

固定墙体建议：

| 墙体 | 中心坐标 m | 尺寸 m | 说明 |
| --- | --- | --- | --- |
| 左中挡板 | (-3.2, 0) | 0.22 x 1.8 | 限制横向直线滑出 |
| 右中挡板 | (3.2, 0) | 0.22 x 1.8 | 与左侧对称 |
| 上中央挡板 | (0, 1.9) | 1.8 x 0.22 | 制造上路绕行 |
| 下中央挡板 | (0, -1.9) | 1.8 x 0.22 | 制造下路绕行 |

这些墙体为地图永久墙，默认不可破坏。P1 可加入可破坏地图墙。

### 2.3 临时墙体合法性

临时墙体放置时必须满足：

- 不与任一角色圆形碰撞体重叠。
- 不与已有墙体重叠超过 20% 面积。
- 不完全切断任一角色到地图中心的路径。
- 不超过所属玩家临时墙数量上限。
- 墙体中心必须在地图安全区内。

P0 如果路径检测成本过高，可使用简化规则：

- 临时墙不能放在距离角色 0.8 m 内。
- 临时墙不能放在地图中心半径 0.8 m 内。
- 每名玩家最多同时存在 2 段临时墙。

### 2.4 墙体碰撞规则

墙体不可弹性反弹。

推荐计算逻辑：

```text
若角色与墙体重叠：
1. 计算最短推出方向。
2. 将角色推出到合法位置。
3. 法线方向速度 = 0。
4. 切线方向速度 *= (1 - wallFriction)。
```

默认：

- wallFriction = 0.25。
- 临时墙 hp = 1 到 3。
- 地图固定墙 hp = 无限。

## 3. 最新 13 条要求落实检查

以下检查基于当前 `NewProject/assets/scripts/MechanicsBrawlGame.ts` 的 MVP 状态。当前代码已从 v3.x 即时结算原型改为 v4.0 单脚本 MVP：核心规则闭环已落地，但还没有按正式架构拆分为 Match、Round、Turn、Card、Effect、Physics 等模块。

| 序号 | 最新要求 | 当前落实状态 | 说明 |
| --- | --- | --- | --- |
| 1 | 每个玩家行动回合限时 2 分钟，超时自动结束 | 已落实 | `turnTimer = 120`，规划阶段倒计时归零后自动结束行动 |
| 2 | 每回合卡牌作用效果按 1 秒计算，且只在回合结束后起效；新旧有效效果一起作用 | 已落实 | 卡牌进入 `pendingIntents`，回合末骰子后转为场源、墙体或属性效果；旧效果按剩余秒数继续参与 |
| 3 | 回合结束播放掷骰过场，动画后双方在 1 秒内因合力同时移动 | 已落实 | 状态机为 `planning -> turnDice -> settling`，`settling` 固定推进 1 秒 |
| 4 | 增加冰雪、电磁等特效和风雪、电击等音效方向 | 部分落实 | 已有蓝色冰雪/雪花、电磁闪电、WebAudio 临时音效；尚未接正式音乐和美术资源 |
| 5 | 明确质量 kg、距离 m、速度 m/s、电荷 C、作用力 N、动量 kg·m/s | 已落实 | HUD 显示质量、位置、速度、电荷、合力、动量，逻辑地图使用 m |
| 6 | 增加像素风开始界面，开局骰子 1-3 牛顿先手，4-6 麦克斯韦先手 | 已落实 | `start` 和 `firstDice` 阶段已实现 |
| 7 | 单局最多 30 个行动回合，双方各 15 回合；无人出界则按中心距离判胜 | 已落实 | `maxActionTurns = 30`，到达上限后比较中心距离 |
| 8 | 一轮游戏三局两胜制 | 已落实 | `roundWins` 到 2 后进入整场结束 |
| 9 | 增加角色专属卡组和基础数学卡牌，加减乘除必须有边界 | 部分落实 | 已有牛顿/麦克斯韦专属卡与数学牌，加一、半值、倍率已实现；完整加减乘除目标选择仍待 P1 |
| 10 | 增加弃牌功能，避免手牌卡死 | 已落实 | 每行动回合最多弃 2 张，不立即补牌 |
| 11 | 地图加入固定形状刚性墙体，可破坏、可添加、无弹性反弹 | 已落实 | 固定墙、临时墙、破墙和无弹性碰撞已实现；P1 可补路径合法性强化 |
| 12 | 每个角色摩擦系数、质量独立可变；增加弱固定场源卡，鼠标设置位置和方向 | 已落实 | 双角色有独立质量/摩擦/电荷；风场、电荷点、摩擦区可鼠标放置，风场可拖拽定方向 |
| 13 | 取消卡牌基础力，角色只能通过固定场源或自身属性获得受力 | 已落实 | 已移除 `CardDef.power` 与 `addImpulse()`，角色受力来自场源、角色电荷关系、属性和墙体交互 |

结论：

- v4.0 目前已有可运行的单脚本 MVP，能验证核心闭环。
- 当前代码仍属于原型架构。若继续扩展卡池、美术、AI 或多人对战，建议按 v4.0 架构拆分模块，而不是继续在单脚本里堆功能。

## 4. 需要重构的当前代码点

当前 MVP 中与 v4.0 冲突最大的点：

| 当前机制 | 冲突原因 | v4.0 替代 |
| --- | --- | --- |
| `CardDef.power` | 已移除 | 后续数据表应继续使用 `effectType`、`sourceStrength`、`attributeDelta` 等字段 |
| `playSelectedCard()` 立即执行 | 已替换 | 当前改为 `queueSelectedCard()` 生成 `CardIntent` |
| `addImpulse()` | 已移除 | 速度只由统一结算中的合力、质量、摩擦和碰撞计算 |
| `frictionTurns/slopeTurns` | 已替换 | 当前使用 `FieldSource` 和 `AttributeEffect` 管理持续效果 |
| 全局摩擦 | 已替换 | 当前为角色独立摩擦 + 区域摩擦修正 |
| 单脚本绘制和逻辑混杂 | 仍存在 | P0 可接受；P1/P2 应拆分 BattleHud、TurnController、PhysicsWorld、EffectSystem |

## 5. P0 技术验收清单

P0 完成时，程序和策划应共同验收：

- 行动回合倒计时显示 120 秒，并能超时自动结束。
- 使用卡牌只进入计划队列，不立即改变角色属性、场景属性、位置或速度。
- 点击结束后播放临时骰子过场。
- 过场结束后统一结算 1 秒。
- 至少 1 种风场和 1 种电荷点能对双方同时产生可见影响。
- 至少 1 种临时墙能阻挡角色，且不弹性反弹。
- 至少 1 种破墙卡能减少墙体耐久。
- 至少 2 张数学卡牌能合法修改属性并执行边界限制。
- 弃牌能移除手牌，不立即补牌。
- 角色 UI 显示 kg、m、m/s、C、N、kg·m/s。
- 三局两胜和 30 行动回合上限可跑通。

---

## 6. 推荐落地顺序

1. 先做数据结构：CharacterState、CardIntent、EffectInstance、FieldSource、WallBody。
2. 再做 1 秒 PhysicsWorld 结算，允许内部 0.1 秒子步。
3. 再接入计划队列和回合结束按钮。
4. 再实现风场、电荷点、临时墙。
5. 再加入数学卡牌、弃牌和卡组。
6. 最后做像素开始界面、骰子动画、音效和特效。

这样能最早验证核心规则，不会被表现层拖慢。
