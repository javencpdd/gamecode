# 《力学大乱斗》v6.0 抖音小游戏横竖屏自适应策划方案

版本：v6.0  
日期：2026-05-17  
定位：在 v5.0 场源参数化、方块墙体和完整卡池说明基础上，将当前 Cocos MVP 重构为面向抖音小游戏和多客户端的横竖屏自适应体验

---

## 1. 版本目标

v6.0 的核心目标是让当前游戏从单一横屏实验台升级为可按客户端自动切换的横竖屏布局。抖音小游戏默认面向竖屏，但 Web、编辑器预览、平板或其他渠道可能提供横屏窗口，因此游戏内 UI 必须能根据实际可视宽高比选择布局。

本版重点：

1. 保留横屏 1280 x 720 布局，并新增竖屏 720 x 1280 布局。
2. 运行时读取客户端可视宽高比：宽 >= 高时使用横屏布局，宽 < 高时使用竖屏布局。
3. 在横屏或竖屏内部继续按客户端可视尺寸等比缩放，避免大屏过小、小屏溢出。
4. 竖屏下将横向 HUD 改为上中下三段式布局。
5. 竖屏下将横向 6 张手牌改为底部 3 x 2 手牌区。
6. 保持抽牌概率、墙体和 1 秒统一结算框架不变，并优化风场、电荷场和属性牌的物理表达。
7. 为抖音小游戏构建补充默认竖屏方向模板。
8. 手机端启用高设备像素比渲染，避免画布被放大后出现文字和线条模糊。
9. 略微放大比赛场地的米制尺寸，给库仑力结算留出更稳定的距离空间。

## 2. 横竖屏与缩放基础规格

| 项目 | 横屏模式 | 竖屏模式 |
| --- | ---: | ---: |
| 触发条件 | 客户端可视宽度 >= 高度 | 客户端可视宽度 < 高度 |
| 设计分辨率 | 1280 x 720 | 720 x 1280 |
| 画布比例 | 16:9 横屏 | 9:16 竖屏 |
| 战场尺寸 | 13.6 m x 7.6 m | 11.2 m x 8.9 m |
| 像素/米 | 68 px/m | 59 px/m |
| 战场像素尺寸 | 925 x 517 px | 661 x 525 px |
| 手牌布局 | 底部 1 x 6 横排 | 底部 3 x 2 网格 |
| 单张手牌尺寸 | 112 x 70 px | 104 x 82 px |
| 信息布局 | 顶部状态 + 左右角色面板 | 状态、计时、角色面板集中在上半部 |

上表中的像素尺寸是基准尺寸。实际客户端会继续乘以 `layoutScale`。

### 2.1 切换与缩放规则

当前实装规则：

```text
if visibleWidth >= visibleHeight:
    使用横屏布局
    baseWidth = 1280
    baseHeight = 720
else:
    使用竖屏布局
    baseWidth = 720
    baseHeight = 1280

layoutScale = min(visibleWidth / baseWidth, visibleHeight / baseHeight)
实际画布宽高 = visibleWidth x visibleHeight
UI 坐标、按钮、手牌、字体、战场像素/米 = 基准值 x layoutScale
```

游戏每帧检查一次可视尺寸；当客户端窗口比例或尺寸变化时，只切换布局参数和 UI 缩放，不重置战局、不重抽手牌、不清空计划队列。角色位置会被 clamp 到当前战场边界内，避免旋转或窗口变化后角色落到战场外。

缩放目标：

- 任何横屏尺寸都保持 16:9 基准构图比例，额外空间作为舒适留白。
- 任何竖屏尺寸都保持 9:16 基准构图比例，额外空间作为舒适留白。
- 字号、按钮、手牌和场源预览圈同步缩放，避免只缩战场、不缩 HUD 的割裂感。
- 字号设置最小保护值，避免小屏缩放后文字低于可读范围。

### 2.2 清晰度策略

手机端画面清晰度由三层保证：

1. 渲染层启用 Retina/高 DPR 支持，内部画布按设备像素比输出，而不是把低分辨率画布直接放大。
2. 布局层保留横屏 1280 x 720、竖屏 720 x 1280 的设计坐标基准，避免在普通手机上把文字缩到过小字号。
3. 移动端文字设置最低可读字号，关键描边线宽按布局比例取整，减少半像素描边造成的发虚。

## 3. 竖屏界面布局

竖屏采用上中下三段式：

| 区域 | 坐标范围 | 内容 |
| --- | --- | --- |
| 顶部信息区 | y = 260 到 640 | 标题、回合信息、计时、场源/墙体概览、双方角色状态、重开/弃牌/结束按钮 |
| 中央战场区 | 约 y = -259 到 259 | 实验台、场源、墙体、角色、受力箭头、计划预览 |
| 底部操作区 | y = -640 到 -275 | 操作提示、卡牌详情、3 x 2 手牌区 |

### 3.1 顶部信息区

顶部信息区承担原横屏左/右角色面板和顶部状态栏的功能。

布局规则：

- 标题固定在顶部。
- 回合信息和倒计时并排显示。
- 场源、墙体和本回合计划使用一行可换行摘要。
- 牛顿与麦克斯韦的状态面板左右并排，显示位置、速度、质量、摩擦、电荷、合力、动量和边界距离。
- 重开、弃牌、结束/跳过按钮放在战场上沿上方，避免和底部手牌争抢触摸区域。

### 3.2 中央战场区

战场从横向长方形改为更接近竖屏的中型实验台。

规则：

- 地图尺寸为 11.2 m x 8.9 m。
- 初始角色位置从 x = ±4.6 m 调整为 x = ±3.8 m。
- 初始墙体改为围绕中心的四段可破坏墙：
  - 左右竖墙：x = ±2.8 m，尺寸 0.4 m x 2.2 m。
  - 上下横墙：y = ±2.35 m，尺寸 2.4 m x 0.4 m。
- 原有出界、碰撞、场源、墙体、边界距离计算规则保持不变。

### 3.3 底部操作区

底部操作区服务移动端触控：

- 手牌固定为 3 列 x 2 行。
- 上排为第 1 到 3 张，下排为第 4 到 6 张。
- 卡牌区域更高，便于显示双行短名。
- 点击卡牌查看说明。
- 拖拽卡牌到中央战场释放。
- 场源卡释放后仍打开参数面板，确认后才消耗手牌。

## 4. 抖音小游戏方向配置与客户端差异

v6.0 增加抖音小游戏构建模板：

```text
NewProject/build-templates/bytedance-mini-game/game.json
```

模板内容：

```json
{
  "deviceOrientation": "portrait"
}
```

目的：

- 构建抖音小游戏时默认输出竖屏方向，符合抖音小游戏常见运行形态。
- 避免只改 Cocos 场景画面，但小游戏运行容器仍按横屏处理。
- 让后续构建产物与 v6.0 竖屏 UI 保持一致。

注意：

- 游戏代码本身已经支持横竖屏自适应。
- 抖音小游戏外层容器方向仍由 `game.json` 决定；如果某个渠道包需要强制横屏，需要在该渠道构建前将 `deviceOrientation` 改为横屏方向。
- Web、编辑器预览或允许窗口自由变化的客户端，会按实际可视宽高比自动切换。

## 6. 卡牌与抽牌规则

v6.0 保留 v5.0 的卡牌数量、抽牌节奏和抽取权重，但对部分卡牌的物理表达做规则优化。

当前卡牌数据：

- 唯一卡牌总数：21 张。
- 牛顿实际可抽牌库：17 张。
- 麦克斯韦实际可抽牌库：17 张。
- 开局双方各抽 4 张。
- 每个行动回合开始抽 2 张。
- 手牌上限 6 张。
- 每回合最多弃 2 张。
- 每回合最多计划 1 张基础数学牌。
- 牌库不抽空；每次抽牌都按完整角色牌库权重重新随机。

当前抽取权重仍沿用 v5.0：

| 卡牌类型 | 基础权重 |
| --- | ---: |
| 角色属性/其他牌 | 1.30 |
| 基础数学牌 | 0.90 |
| 摩擦/阻尼区域 | 0.75 |
| 风场/电荷场源 | 0.55 |
| 建墙/破墙 | 0.22 |

墙体同类降权仍保留：

```text
若手牌中已经有同类建墙牌或破墙牌，则同类卡权重 x0.35
```

### 6.1 物理卡牌优化

#### 库仑力

电荷场和角色之间的电荷作用不再用“设置最大力 + 距离衰减”的近似规则，而是按库仑形式计算：

```text
F = k * q1 * q2 / r_eff^2
r_eff = max(实际距离, 最小距离)
```

- 同号电荷相斥，异号电荷相吸。
- 最小距离用于限制初始峰值，避免两个电荷过近时瞬间产生过大的力。
- 电荷场仍保留作用半径，表示该卡牌的有效影响范围。
- 比赛场地米制尺寸略微扩大，开局距离增加，降低初始库仑力过大导致的随机性。
- 角色之间的自然电荷作用使用 `k=0.36`、作用距离 `5.8 m`、最小距离 `1.05 m`。
- 麦克斯韦作为电磁主题角色，电荷场参数只保留轻微优势：范围、源电荷和 k 值略高于通用电荷场，但最小距离仍接近通用电荷场。

| 卡牌 | v6.0 规则 |
| --- | --- |
| 静电标记 | 半径 3.4 m；源电荷 0.8-2.0 C；`k=0.54`；最小距离 0.95 m；持续 4 s |
| 微型电荷点 | 半径 3.7 m；源电荷 1.0-2.3 C；`k=0.56`；最小距离 0.90 m；持续 4 s |

#### 矩形风场

风场不再使用圆形作用范围。因为风力有固定方向，v6.0 改为以放置点为中心、沿风向旋转的矩形风道：

| 卡牌 | v6.0 规则 |
| --- | --- |
| 轻风标记 | 矩形 4.6 m x 1.8 m；风力 0.30-1.60 N；持续 3 s |
| 风矢量 | 矩形 5.2 m x 2.0 m；风力 0.40-1.90 N；持续 3 s |

角色中心点进入矩形范围后，受到固定方向风力；离开矩形范围后不再受该风场影响。

#### 质量、电荷和强化牌

属性牌不再全部用简单加减处理，允许乘除倍率：

| 卡牌 | v6.0 规则 |
| --- | --- |
| 轻量校准 | 自身质量 x0.82，持续 2 s |
| 重量校准 | 自身质量 x1.18，持续 2 s |
| 惯性锁定 | 自身质量 x1.35，持续 2 s |
| 乘法校准 | 自身质量 x1.5，持续 1 s |
| 放电校准 | 对手电荷 x0.65，一次性 |
| 半值衰减 | 对手电荷 /2，一次性 |
| 电荷翻转 | 对手电荷 x-1，一次性 |
| 稳定鞋钉 | 自身摩擦 x1.35 后 +0.02，持续 2 s |
| 倍率放大 | 最近己方场源 x1.5：风场提高风力，电荷场提高源电荷，摩擦/阻尼区提高区域系数 |

质量仍限制在 0.5-5.0 kg，电荷仍限制在 -5 到 5 C，摩擦仍限制在 0.02-0.80。

## 7. 移动端触控原则

竖屏后需要坚持以下交互规则。手机端不依赖桌面鼠标事件，所有点击、拖拽、松手都必须同时接入触摸输入：

1. 主要可点击按钮高度不低于 40 px。
2. 手牌区域固定在底部，避免和战场拖放区域混在一起。
3. 卡牌详情文本在手牌上方，玩家选牌后不遮挡战场中心。
4. 场源参数面板居中弹出，仍允许查看场源预览圈。
5. 战场边缘必须始终可见，避免玩家误判出界距离。
6. 角色名称仍显示在角色头顶，但不得遮挡顶部角色面板。
7. 桌面端监听 `MOUSE_DOWN / MOUSE_MOVE / MOUSE_UP`，移动端监听 `TOUCH_START / TOUCH_MOVE / TOUCH_END / TOUCH_CANCEL`。
8. 鼠标和触摸事件统一转换为游戏内本地坐标，并复用同一套按钮点击、手牌选择、卡牌拖拽和释放逻辑。
9. 触摸触发后短时间内忽略浏览器或小游戏容器可能补发的鼠标事件，避免一次点击被执行两次。

## 8. v6.0 验收标准

v6.0 至少满足：

- 竖屏客户端下，游戏以 720 x 1280 为基准，并缩放到实际可视尺寸。
- 横屏客户端下，游戏以 1280 x 720 为基准，并缩放到实际可视尺寸。
- 客户端宽高比变化时，UI 能自动切换横竖屏布局。
- 客户端尺寸变化但方向不变时，UI、手牌、字体、战场像素/米按 `layoutScale` 等比缩放。
- 竖屏战场米制尺寸为 11.2 m x 8.9 m，横屏战场米制尺寸为 13.6 m x 7.6 m。
- 手机端画布启用高 DPR/Retina 渲染，文字、卡牌边框、战场网格和按钮描边不应明显发虚。
- 标题显示为 `力学大乱斗 v6.0`。
- 竖屏下中央战场完整显示，不被顶部信息区和底部手牌区遮挡。
- 竖屏下双方角色状态面板在顶部并排显示。
- 竖屏下手牌以 3 x 2 网格显示，6 张牌都可点击和拖拽。
- 横屏下保留原有 1 x 6 手牌和左右角色面板布局。
- 卡牌拖入战场后能正常进入计划队列。
- 场源卡仍能打开参数面板并确认方向/数值。
- 电荷场按库仑公式结算，并通过最小距离限制峰值。
- 风场作用区域为沿风向旋转的矩形，而不是圆形半径。
- 质量、电荷和场源强化牌支持乘除倍率，并继续遵守质量、电荷、摩擦边界。
- 重开、弃牌、结束/跳过按钮在竖屏下可点击。
- 手机端开始界面、重开、弃牌、结束/跳过、卡牌拖拽均通过触摸输入正常响应。
- 抖音小游戏构建模板包含 `deviceOrientation: portrait`。
- 抽牌概率、墙体、音频和 1 秒统一结算流程没有被破坏。

## 9. 后续风险

主要风险：

- 不同手机屏幕存在刘海、状态栏和安全区差异，后续应接入平台安全区信息做顶部避让。
- 720 x 1280 和 1280 x 720 只是基准布局，真实设备会动态缩放；后续仍需在真机上确认极端比例的留白是否舒适。
- 角色状态面板信息量较大，长中文文本在小屏上可能需要二级详情面板。
- 3 x 2 手牌适合 6 张上限；如果后续手牌上限提高，需要改为横向滑动或分页。
- 场源参数面板目前仍是居中面板，后续可以改为下半屏抽屉，减少遮挡战场。
